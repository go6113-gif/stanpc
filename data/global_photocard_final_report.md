## 0. 수집 방법 및 데이터 신뢰도 고지

### 0.1 eBay 수집 — Finding API 은퇴에 따른 Browse API 전환

지시대로 `EBAY_APP_ID`(프로젝트 보유 키 `EBAY_CLIENT_ID` = `MOONKYUL-Sta...3dc3`)를 적용해 **eBay Finding API(`findItemsByKeywords`)를 1순위로 호출**했으나, eBay가 레거시 `svcs.ebay.com` Finding 서비스를 은퇴시켜 **HTTP 418**을 반환했습니다(SOA 헤더 방식·쿼리스트링 방식 모두 동일).

```
[12:41:57] 🧪 eBay Finding API 가용성 점검 중...
[12:41:57]    └ Finding API 사용 불가 (HTTPError: HTTP Error 418: I'm a teapot)
[12:41:57]    └ eBay 공식 후속 API인 Browse API로 자동 전환
```

이에 따라 **eBay가 지정한 공식 후속 API인 Browse API(`buy/browse/v1/item_summary/search`, OAuth client_credentials)** 로 자동 전환해 수집했습니다. Finding API가 제공하던 항목(제목·가격·배송비·상태·카테고리·판매자)은 Browse API로 모두 동등하게 확보되어 분석 요구사항에 결손은 없습니다. 사용된 API는 결과 파일 `meta.api_used`에 `"browse"`로 기록되어 있습니다.

| 항목 | 값 |
|---|---|
| 요청 API / 실제 사용 API | `finding` → `browse` (자동 전환) |
| 마켓플레이스 | EBAY_US |
| 검색 키워드 | 5개 그룹 30개 |
| 수집 원본 / 중복 제거 후 | 11,266건 → **9,643건** (itemId 기준 dedup, 중복률 14.4%) |
| 키워드별 eBay 전체 매물 총합 | **384,643건** (교차 중복 포함, 모집단 규모 참고치) |

### 0.2 데이터 신뢰도에 관한 3가지 주의사항 (해석 전 반드시 확인)

1. **DCInside 60건은 소표본입니다.** `data/dcinside_raw.json`은 검색 결과 3개 페이지의 HTML로, 실제 추출 가능한 게시물 제목은 3개 키워드 × 20건 = **60건**입니다. 별도 파일 `data/community_insights.json`은 12건 표본의 정성 분석이므로, 본 보고서에서 DCInside는 **정량 근거가 아닌 국내 커뮤니티 정성 참조**로만 사용합니다.
2. **Naver 6,707건은 검색 시드 편향이 있습니다.** 5개 시드 키워드(`포카 수집` 1,434 / `포토카드 교환` 1,412 / `포토카드 바인더` 1,410 / `포토카드 판매` 1,245 / `포카 덕질` 1,206)로 균등 수집되어, 시드 단어 자체의 출현률은 인위적으로 부풀려집니다. 본 보고서는 **시드 제외 순수 출현률**을 병기해 이 편향을 보정했습니다(§3.2).
3. **Bluesky·Tumblr에는 비(非)K-POP TCG 노이즈가 섞여 있습니다.** Bluesky 2,372건 중 K-POP 관련은 1,521건(64.1%), 포켓몬·TCG 등 타 카드군 노이즈가 181건(7.6%)입니다. Tumblr는 K-POP 관련 416건(68.9%), 노이즈 3건(0.5%)으로 순도가 높습니다.

### 표 1-2. eBay 제외 — "커뮤니티 4대 플랫폼"만의 실제 균형

eBay는 정의상 100% 거래이므로 전체 평균을 왜곡합니다. 커뮤니티 4개 플랫폼(9,743건)만 보면 균형이 완전히 달라집니다.

| 구분 | 건수 | 비중 |
|---|---:|---:|
| 수집/자랑/소통 | 3,872 | **39.7%** |
| 거래/판매 | 3,919 | **40.2%** |
| 기타(중립 대화) | 1,952 | 20.0% |
| 합계 | 9,743 | 100% |

> **핵심 해석 ①** — 커뮤니티에서 수집축(39.7%)과 거래축(40.2%)은 **0.5%p 차이의 완전한 동률**입니다. "포토카드 서비스 = 거래 플랫폼"이라는 통념은 eBay라는 단일 마켓이 만든 착시이며, 유저가 실제로 시간을 쓰는 행위는 거래와 보관·자랑이 정확히 반반입니다. **거래 기능만 있는 앱은 유저 행동의 절반을 버리는 설계입니다.**

## 5. 결론 — 3문장 요약

1. **19,386건 중 70.0%가 거래 신호이지만, 이는 eBay 9,643건이 만든 착시입니다.** 커뮤니티 4개 플랫폼만 보면 수집·자랑(39.7%)과 거래(40.2%)가 정확히 동률이며, 거래 전용 앱은 유저 행동의 절반을 놓칩니다.
2. **바인더·보관 니즈는 6,886건(35.5%)으로 5개 플랫폼 전부에서 상위권을 차지하는 유일한 니즈**이고, 규격 체계는 A5·3x3·mm·pocket으로 파편화(디바이더 언급 0건, B5 1건)되어 있어 **My Vault의 규격 표준 스키마가 최우선 진입점**입니다.
3. **중앙값 $12.99 카드에 배송비 $8.00(40.9%)** 이라는 구조적 비효율과 Tumblr 교환 언급률 15.2%가 WTT의 수요를 증명하지만, 매칭에는 Vault(보유 목록)와 Wiki(카드 식별자)가 선행되어야 하므로 **Vault → Wiki → WTT 순서가 정량·구조 양면에서 확정적**입니다.
